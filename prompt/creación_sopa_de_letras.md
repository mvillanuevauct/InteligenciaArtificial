# 1. PROPÓSITO

Este prompt tiene como objetivo generar actividades didácticas
interactivas mediante inteligencia artificial generativa.

Las actividades deben combinar:

- Diseño instruccional.
- Metodologías activas.
- Evaluación formativa.
- Retroalimentación inmediata.
- Gamificación educativa.
- Accesibilidad digital.
- Experiencia de usuario (UX).
- Diseño de interfaces (UI).
- Desarrollo web frontend.

El resultado debe ser un recurso educativo digital funcional,
reutilizable y adaptable a diferentes disciplinas universitarias.

Las actividades deben promover la participación activa del
estudiantado y contribuir al logro de resultados de aprendizaje.

# 4. PRINCIPIOS PEDAGÓGICOS OBLIGATORIOS

La actividad debe diseñarse considerando los siguientes principios.

## 4.1 Aprendizaje centrado en el estudiante

El estudiante debe participar activamente en la construcción
de su aprendizaje.

Evitar actividades que se limiten a presentar información.

Priorizar acciones como:

- Identificar.
- Relacionar.
- Clasificar.
- Resolver.
- Interpretar.
- Comparar.
- Aplicar.
- Tomar decisiones.

## 4.2 Coherencia pedagógica

Debe existir coherencia entre:

RESULTADO DE APRENDIZAJE
        ↓
CONTENIDOS
        ↓
ACTIVIDAD INTERACTIVA
        ↓
EVIDENCIA DE APRENDIZAJE
        ↓
RETROALIMENTACIÓN

Las interacciones deben responder al propósito formativo.

## 4.3 Evaluación formativa

Incorporar mecanismos que permitan al estudiante:

- Identificar respuestas correctas.
- Reconocer errores.
- Comprender por qué una respuesta es incorrecta.
- Recibir orientaciones para mejorar.
- Monitorear su progreso.

La evaluación debe contribuir al aprendizaje y no
limitarse a asignar una puntuación.

## 4.4 Aprendizaje autónomo

La actividad debe poder desarrollarse sin intervención
permanente del docente.

Debe incluir:

- Instrucciones claras.
- Ejemplos cuando sean necesarios.
- Retroalimentación automática.
- Indicadores de progreso.
- Mensaje de finalización.

## 4.5 Inclusión y accesibilidad

Considerar principios del Diseño Universal para
el Aprendizaje (DUA).

Incorporar alternativas de interacción cuando
la naturaleza de la actividad lo permita.

1. Contraste adecuado entre texto y fondo.
2. Navegación mediante teclado.
3. Indicadores visibles de foco.
4. Etiquetas accesibles.
5. Instrucciones comprensibles.
6. Tamaños de controles adecuados.
7. Retroalimentación no basada exclusivamente en colores.
8. Compatibilidad razonable con lectores de pantalla.

proporcionar una alternativa mediante clics o teclado.

# 9. RETROALIMENTACIÓN PEDAGÓGICA

La retroalimentación debe ser específica.

Evitar mensajes genéricos como:

"Incorrecto"

Preferir mensajes como:

"Esta respuesta no es correcta porque..."

Cuando el estudiante responda correctamente:

- Confirmar la respuesta.
- Explicar brevemente el concepto.
- Relacionarlo con el contenido del curso.

Cuando responda incorrectamente:

- Identificar el error.
- Entregar una pista.
- Permitir un nuevo intento.
- Explicar la respuesta correcta cuando corresponda.

No utilizar mensajes que desmotiven o ridiculicen
al estudiante.

# 11. CONFIGURACIÓN ESPECÍFICA:
# SOPA DE LETRAS INTERACTIVA

Esta sección se aplica cuando el docente selecciona
una sopa de letras.

## 11.1 Tablero

Tamaño:

[INSERTAR FILAS] x [INSERTAR COLUMNAS]

Ejemplo:

20 x 20

Cantidad de palabras:

[INSERTAR CANTIDAD]

Ejemplo:

12 conceptos.

## 11.2 Distribución

Las palabras deben ubicarse:

- Horizontalmente.
- Verticalmente.
- Diagonalmente.

Permitir direcciones inversas cuando la dificultad
seleccionada lo justifique.

## 11.3 Generación

Implementar un algoritmo que:

1. Normalice las palabras para el tablero.
2. Elimine espacios cuando corresponda.
3. Gestione correctamente tildes y caracteres especiales.
4. Verifique la longitud de cada palabra.
5. Distribuya las palabras sin conflictos.
6. Permita cruces de letras compatibles.
7. Complete espacios vacíos con letras aleatorias.
8. Registre las coordenadas reales de cada palabra.
9. Verifique que todas las palabras estén insertadas.
10. Evite declarar una palabra como encontrada si
    la selección no coincide con una ubicación válida.

No generar palabras únicamente como texto decorativo.

Todas deben existir realmente en la matriz.

Si una palabra no puede insertarse:

- Reintentar la generación.
- Modificar su ubicación.
- Informar el problema si no puede resolverse.

Nunca mostrar una palabra imposible de encontrar.

## 11.4 Interacción

Permitir:

- Selección mediante ratón.
- Arrastre continuo.
- Interacción táctil.
- Selección alternativa mediante teclado.

Durante la selección:

Resaltar las celdas seleccionadas.

Al verificar:

Comparar la selección con las coordenadas
registradas de las palabras.

Si es correcta:

- Resaltar permanentemente.
- Marcar el concepto como encontrado.
- Actualizar el progreso.
- Mostrar retroalimentación.

Si es incorrecta:

- Informar el resultado.
- Permitir corregir.
- No penalizar automáticamente.

## 11.5 Panel de conceptos

Mostrar todos los conceptos.

Cada concepto debe tener:

- Nombre.
- Estado.
- Indicador visual.

Estados:

Pendiente
Encontrado

Al encontrarlo:

Mostrar:

✓ Concepto encontrado

## 11.6 Comprensión conceptual

Cuando el estudiante encuentre una palabra:

Mostrar una ventana con:

- Nombre del concepto.
- Definición breve.
- Pregunta de comprensión.
- Tres alternativas.

Solo una alternativa debe ser correcta.

Las alternativas incorrectas deben ser plausibles
y pedagógicamente pertinentes.

La pregunta debe evaluar comprensión y no limitarse
a repetir literalmente la definición.

## 11.7 Validación conceptual

La actividad debe distinguir dos estados:

1. Palabra localizada.
2. Concepto comprendido.

Encontrar una palabra no equivale automáticamente
a demostrar comprensión.

Registrar ambos avances por separado.

Ejemplo:

Palabras encontradas: 8/12

Conceptos comprendidos: 6/12

## 11.8 Finalización

La actividad termina cuando:

- Todas las palabras fueron encontradas.
- Todas las preguntas fueron respondidas correctamente.

Mostrar:

"¡Felicitaciones! Has completado la actividad."

Incluir un resumen del desempeño.

# 12. CONFIGURACIÓN DE CONTENIDOS

Los contenidos deben ser editables.

Utilizar una estructura de datos similar a:

const conceptos = [
  {
    palabra: "ALGORITMO",
    definicion: "Secuencia ordenada de instrucciones.",
    pregunta: "¿Qué caracteriza a un algoritmo?",
    alternativas: [
      "Una secuencia de pasos",
      "Un dispositivo físico",
      "Un archivo multimedia"
    ],
    correcta: 0,
    retroalimentacion:
      "Un algoritmo describe una secuencia de instrucciones."
  }
];

El docente debe poder modificar:

- Palabras.
- Definiciones.
- Preguntas.
- Alternativas.
- Respuestas correctas.
- Retroalimentación.

Sin necesidad de modificar la lógica principal.
