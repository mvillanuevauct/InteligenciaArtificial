# Prompt Maestro para Infografías Académicas de Redes

Plantilla reutilizable para analizar material académico de **Redes de Computadores** y transformarlo en una serie coherente de infografías educativas.

---

## 🎯 Propósito

Este prompt permite transformar una presentación, PDF o documento académico en una colección de infografías orientadas al aprendizaje de Redes de Computadores.

El proceso debe priorizar:

- Exactitud técnica.
- Coherencia pedagógica.
- Claridad visual.
- Continuidad entre infografías.
- Fidelidad al documento fuente.
- Aplicación práctica de los conceptos.

> **Principio fundamental:** la exactitud técnica tiene prioridad sobre la estética.

---

# 👤 Rol solicitado

Quiero que actúes como:

- Diseñador instruccional.
- Académico universitario.
- Especialista en Redes de Computadores.
- Especialista en tecnologías Cisco.
- Diseñador de infografías educativas.

Voy a adjuntar una presentación, PDF o documento correspondiente a un módulo de una asignatura de Redes de Computadores.

Tu trabajo será analizar **EXCLUSIVAMENTE el material adjunto** y transformarlo en una serie de infografías académicas que puedan utilizarse como material complementario para estudiantes.

---

# FASE 1 — ANÁLISIS DEL MATERIAL

Antes de generar cualquier imagen:

## 1. Revisar completamente el documento

Analiza completamente el documento adjunto antes de realizar propuestas o generar imágenes.

No te limites únicamente a:

- títulos;
- índice;
- primeras diapositivas;
- resumen final.

Considera la totalidad del contenido disponible.

---

## 2. Identificar los contenidos relevantes

Identifica, cuando estén presentes:

- Conceptos fundamentales.
- Funcionamiento de protocolos o tecnologías.
- Arquitecturas.
- Topologías.
- Configuraciones.
- Comandos Cisco IOS.
- Procedimientos.
- Mecanismos de verificación.
- Troubleshooting.
- Buenas prácticas.
- Comparaciones importantes.
- Amenazas.
- Vulnerabilidades.
- Mecanismos de mitigación.
- Ejercicios prácticos.
- Laboratorios.
- Actividades Packet Tracer.

---

## 3. Mantener la terminología original

Mantén la terminología técnica utilizada en el documento original.

No reemplaces conceptos técnicos por otros términos si ello puede modificar su significado.

Cuando corresponda, conserva términos ampliamente utilizados en redes como:

- Access.
- Trunk.
- VLAN.
- Routing.
- Switching.
- Port Security.
- DHCP Snooping.
- Dynamic ARP Inspection.
- PortFast.
- BPDU Guard.
- Router-on-a-Stick.
- SVI.
- OSPF.
- BGP.
- GRE.
- IPSec.

---

## 4. No inventar información

No inventes:

- Configuraciones.
- Comandos.
- Direcciones IP.
- Máscaras.
- Prefijos.
- VLAN.
- Interfaces.
- Características.
- Protocolos.
- Valores.
- Funcionalidades.

Todo contenido técnico debe estar respaldado por el material analizado.

---

## 5. Información faltante

Si detectas que un concepto importante requiere información que no aparece en el documento:

1. No la incorpores automáticamente.
2. Indica qué información falta.
3. Explica brevemente por qué sería útil.
4. Espera autorización antes de complementarla con conocimiento externo.

---

# FASE 2 — PROPUESTA DE INFOGRAFÍAS

No intentes colocar todo el módulo en una única imagen.

Divide los contenidos aproximadamente en **4 a 6 infografías**, dependiendo de:

- Extensión del módulo.
- Complejidad técnica.
- Cantidad de configuraciones.
- Cantidad de conceptos.
- Existencia de procedimientos.
- Necesidad de troubleshooting.

Los títulos deben ser:

# 🔗 REPRESENTACIÓN DE ENLACES FÍSICOS Y TRÁFICO LÓGICO

## Regla fundamental

Nunca representar una VLAN como si fuera un enlace físico independiente.

Si varias VLAN utilizan el mismo enlace físico trunk:

- Representar el enlace físico mediante una **línea continua**.
- Representar el tráfico lógico mediante **líneas discontinuas**.
- Utilizar el color asignado a cada VLAN.

### Ejemplo

```text
SW1 ═══════════════════════════════ SW2
           TRUNK 802.1Q
           enlace físico

     - - - - - - - - - - -
          Tráfico VLAN 10

     - - - - - - - - - - -
          Tráfico VLAN 20
```

La representación debe permitir diferenciar claramente:

```text
ENLACE FÍSICO ≠ TRÁFICO LÓGICO
```

# 4. FUNCIONAMIENTO

Cuando ayude a comprender el protocolo o tecnología, explica gráficamente el flujo.

Utiliza secuencias como:

```text
1 → 2 → 3 → 4 → 5
```

Cada etapa debe indicar claramente qué sucede con:

- El dispositivo.
- El paquete o trama.
- La interfaz.
- El protocolo.
- La VLAN.
- El encabezado.
- La decisión tomada por el dispositivo.

---

# 5. CONFIGURACIÓN

Cuando existan configuraciones Cisco IOS, presenta bloques CLI claros.

### Ejemplo

```text
SW1(config)# interface fa0/1
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 10
```

## Regla

No alterar la sintaxis de los comandos proporcionados por el material original.

Los comandos deben:

- Estar completos.
- Mantener su orden lógico.
- Utilizar interfaces coherentes con la topología.
- Utilizar las mismas VLAN mostradas en el diagrama.
- Utilizar el mismo direccionamiento definido previamente.

---

# 6. VERIFICACIÓN

Incluye los comandos necesarios para comprobar el funcionamiento.

Dependiendo del contenido pueden aparecer, por ejemplo:

```text
show vlan brief
show interfaces trunk
show interfaces switchport
show ip interface brief
show ip route
show port-security
show port-security interface
show ip dhcp snooping
show ip dhcp snooping binding
show spanning-tree
ping
```

Utiliza solamente aquellos comandos que correspondan al contenido analizado.

---

# 7. ERRORES FRECUENTES / TROUBLESHOOTING

Cuando sea pertinente, incorpora un bloque visual:

```text
ERRORES FRECUENTES
```

Incluye aproximadamente **3 a 5 errores** que los estudiantes deberían revisar.

Una estructura útil puede ser:

| Problema | Causa probable | Verificación | Acción |
|---|---|---|---|
| Sin conectividad | VLAN incorrecta | `show vlan brief` | Revisar VLAN |
| Trunk no funciona | Puerto mal configurado | `show interfaces trunk` | Revisar trunk |
| Gateway inaccesible | Direccionamiento incorrecto | `show ip interface brief` | Revisar IP |
